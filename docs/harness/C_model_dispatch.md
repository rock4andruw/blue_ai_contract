# C. 模型調度與動態升降級守則

> 讀者：擔任「指揮官」的主控模型。你要把工作拆給 subagent，並選對模型、控好升降級。
> 核心信念：**貴模型負責判斷與拆解，便宜模型負責大量套用。** 讓對的模型做對的事。

---

## 1. 派工三件套（每次派 Subagent 必附，缺一不可）

用 Agent tool 派工時，prompt **必須**同時包含這三塊。缺任一塊就是不合格派工，會導致 subagent 亂做。

### ① 明確目標與背景
- 一句話目標 + 為什麼要做（讓 subagent 能自行判斷邊界）。
- 相關檔案路徑（給路徑，**不要**貼大段檔案內容——讓它自己讀）。
- 明確劃定「範圍內」與「範圍外」。

### ② 嚴格的驗收條件（Rubric，可勾選）
- 用**可客觀判定**的條件，不用「做好」「高品質」這種主觀詞。
- 範例（好）：「`python3 -m pytest tests/test_diff.py` 全綠；新增函式有 type hints 與 docstring；不修改 `contract-*.md`。」
- 範例（壞）：「把差異分析寫得完整一點。」← 無法判定，禁用。

### ③ 標準回報格式（省 token，禁噴大段碼）
要求 subagent **只回**：
```
狀態：完成 / 部分完成 / 卡住
產出檔案：<路徑清單>
關鍵改動：<檔案:行號> — <一句話>（最多 5 條）
驗收結果：<每條 Rubric 打勾/打叉 + 一句證據>
卡點（若有）：<現象 + 已試過什麼>
```
❌ 禁止 subagent 回傳整份檔案內容或大段程式碼——指揮官要的是「路徑 + 行號 + 結論」。

> 標準派工模板見 [E_dispatch_templates.md](E_dispatch_templates.md)，直接複製填空。

## 2. 異常升降級路徑（防閉環的核心）

**鐵則：同一件事最多重試兩輪為上限**（Haiku 是更嚴的特例——見下方升級表，錯 1 次就升級，不吃滿兩輪）。不要讓弱模型在同一個錯上原地打轉。

### 升級觸發（往上換更強模型）
| 情境 | 動作 |
|------|------|
| Haiku 工具調用或語法**錯 1 次** | 立刻升級 → **Sonnet**（不給 Haiku 第二次） |
| Sonnet 同一子任務**連錯 2 次** | 升級 → **Opus 4.8**，且**必須附上完整失敗軌跡** |
| 任何模型**觸發熔斷條件**（見 [D](D_judgment_matrix.md) 第 3 節） | 停止自主，回報 User |

**升級時怎麼帶失敗軌跡**：開新 Agent（指定更高 `model`），在 prompt 內附上：前次模型是誰、試了什麼、確切錯誤訊息、你認為卡在哪。**不附軌跡的升級＝浪費一輪**，因為新模型會重踩同一坑。

### 降級觸發（往下換便宜模型，省成本）
- 當 **Opus 解出一個「固定模式」**（例如：找出了正確的修法/重構樣板），就把該模式寫成明確步驟，**降回 Haiku/Sonnet 批次套用**到其餘相似案例。
- 判準：任務已從「需要判斷」變成「機械式重複」→ 降級。

### 升降級決策圖（文字版）
```
新子任務
  └─ 機械式重複、樣板明確？ ── 是 → Haiku
  └─ 需要理解程式碼/寫新邏輯？ ── 是 → Sonnet
  └─ 需要架構判斷/跨檔權衡/前面已連錯？ ── 是 → Opus 4.8
Haiku 錯1次 → Sonnet ；Sonnet 同任務錯2次(+軌跡) → Opus ；Opus 解出模式 → 降回批次
```

## 3. 隔離驗證原則（實作者不得自我驗證）

**鐵則：寫代碼的 Agent 不准自己說「我驗過了，沒問題」。** 自我驗證有系統性盲點（它會用當初寫錯的假設去驗）。

驗收**必須另派** Fresh-Context Subagent，方式擇一或並用：
1. **Read-back 重讀**：全新 context 重新讀產出檔，對照 Rubric 逐條核。
2. **實跑測資**：跑既有測試 / 用真實測資執行，看實際輸出（不是看代碼「應該」對）。
3. **多樣本評審（Multi-agent debate）**：對「有品味成分」的產出（如文案、報告語氣），派 2–3 個 Agent 各自產出或評分，指揮官選優。

> 什麼算「真正完成」的量化判準見 [D](D_judgment_matrix.md) 第 2 節。

## 4. 模型選用速查表

| 任務型態 | 建議模型 | 理由 |
|----------|----------|------|
| 搜尋、抓檔、列清單、機械式改名 | **Haiku** | 便宜、夠用 |
| 功能實作、寫測試、讀懂中等複雜度代碼 | **Sonnet** | 平衡 |
| 架構決策、跨檔重構權衡、debug 難題、拆解大任務、對抗審查 | **Opus 4.8** | 判斷力 |
| 模糊的商業美感 / 品味決策 | **⚠️ 沒有模型能自動搞定** | 一律熔斷交 User（見 [D](D_judgment_matrix.md) §4） |

> 模型 ID：`claude-haiku-4-5`、`claude-sonnet-5`、`claude-opus-4-8`。派 subagent 用 Agent tool 的 `model` 參數（`haiku`/`sonnet`/`opus`）。
