## 二、研究背景與動機

企業合約審查高度依賴法務人力，且錯誤代價極高。國際研究指出：

* 法務人員 **40–60%** 工時耗費於合約起草與審閱（Thomson Reuters）
* 人工審閱一份 NDA 平均耗時 **92 分鐘**，AI 僅需 **26 秒**（LawGeex, 2018）
* 合約管理不善導致企業平均流失 **9.2%** 年營收（WorldCC / IACCM）

現有 AI 合約審查工具（如 LawGeex、LegalOn）以純大型語言模型（LLM）或機器學習方法為主，在企業法律應用中面臨兩項核心問題：

**問題一：高風險條款漏判**
LLM 因語言理解的不確定性，無法保證高風險條款的完整偵測（高召回率）。在法律場景中，任何漏判都可能導致重大商業損失。

**問題二：AI 強制輸出確定答案**
現有工具在語意模糊的條款上仍強制給出 High / Medium / Low 判定。在法律判斷存在真正爭議時，AI 的確定答案反而可能誤導決策者。

此外，台灣目前缺乏針對繁體中文合約、台灣業界慣例的系統性量化研究，是本研究可填補的本地化缺口。

## 三、研究問題

本研究圍繞三個核心問題：

**RQ1**：混合架構（Rule Engine + LLM）相較於純 LLM，是否能在繁體中文合約風險偵測中達到更高的高風險召回率？

**RQ2**：盲評設計（Agent 不知對方答案）是否能有效降低多代理人系統中的 Sycophancy（阿諛奉承偏誤），提升判斷與人工標注的一致性？

**RQ3**（選做）：AI 主動揭露不確定性（Pending 機制）是否改善使用者的決策品質與審閱效率？

## 四、研究方法與系統架構

本研究提出一套三層防禦架構，已完整實作為可運行系統：

```
合約 Diff 輸入
      │
      ├──→ [第一層] 風險規則引擎（Rule Engine）
      │         14 條純程式碼規則，保證高風險 100% 召回率
      │         不依賴 LLM，結果可重現、可驗證
      │
      ├──→ [第二層] 語意補漏掃描（Verification Agent）
      │         LLM 讀取差異條款，捕獲非標準寫法造成的漏判
      │
      └──→ 兩層合併 → [第三層] 多代理人雙重驗證（MAS）
                  Agent A（嚴格派）與 Agent B（平衡派）
                  採用盲評：互不知對方判斷，不知規則引擎結果
                        │
                  Judge 矩陣裁決：
                  gap = 0/1 → confirmed（意見一致，給出確定結論）
                  gap = 2   → pending（真正分歧，建議人工判斷）
```

**設計哲學**：Rule Engine 做判斷（保召回）→ LLM 做解釋（保可讀性）→ MAS 做驗證（保可信度）

## 五、學術創新性

本研究有三項可主張的學術貢獻（優先順序已調整，2026-07-07 更新）：

### **貢獻一（主）：可驗證的三層防禦架構 ★ 核心創新**

針對已知風險類別（15 類），Rule Engine 以純程式規則達到該範圍內 **100% 召回率**（可重現、可驗證）；對規則庫未涵蓋的長尾風險，由 Verification Agent（LLM 語意補漏）進行二層補捉；MAS 機制確保結論可信度。三層互補，形成「已知不漏、未知有網、過程可驗」的防禦架構。

**學術創新點**：
- 現有文獻多採純 LLM（黑箱、無法保證 recall）或純 ML 方法（特徵工程複雜），**缺乏具備「可驗證範圍召回率保證」的混合架構實踐**
- 本研究在繁體中文合約場景首次實證：Rule Engine 的剛性規則能保證高風險 100% 召回，解決純 LLM 無法保證的問題
- Rule Engine + LLM 的**串聯設計**（非融合），使系統在保留確定性判斷的同時，加入 LLM 的語意彈性

> **範圍聲明**：100% 召回率成立於預定義的 15 類風險類別，非對所有合約風險的全面保證。Verification Agent 補捉長尾風險，兩層相輔相成。

### **貢獻二（輔）：盲評 MAS 設計（防止 Sycophancy）**

為實現 C1（防禦架構）的可信度驗證，採用盲評機制：Agent A/B 互不知對方答案，不知規則引擎結果，獨立判斷。基於 *When Truth Is Overridden (2025)* 文獻，在繁體中文合約審查中首次量化驗證。

- 支撐 C1 的可信度保證（而非獨立的主要貢獻）
- Judge 矩陣而非辯論，設計依據 *Judging with Many Minds (2025)*

### **貢獻三（機制）：Pending 機制揭露 AI 不確定性**

當高風險判斷出現真正分歧（gap=2）時，主動標記「待確認」，展示多方 Agent 的觀點，由人工介入判斷。相較現有合約 AI 工具（強制輸出確定答案），本研究證實 AI 主動揭露不確定性更適合法律場景。

## 十、研究限制說明

本研究誠實說明以下已知限制：

1. **召回率範圍**：100% 召回率成立於預定義的 15 類風險類別，並非對所有合約風險的全面保證。對非標準寫法與新型條款，依賴 Verification Agent（LLM 補漏）偵測，此部分無法保證召回率。
2. **LLM 偵測可靠性**：Verification Agent 使用 LLM 進行語意補漏，存在幻覺（hallucination）風險，本研究以 MAS 雙重驗證作為補充防線。
3. **同質模型限制**：Phase 1.5 兩個 Agent 使用相同模型（Gemini），底層偏見一致。未來研究（Phase 2）將引入 Gemini + Claude 異質模型設計。
4. **資料集規模**：80–100 筆樣本在學術標準上屬中等規模，實驗結論需謹慎推廣。
5. **合約類型**：目前以 SLA 與 NDA 為主，採購合約等其他類型有待後續擴充。

## 十一、未來研究方向

1. **LLM 語意解析 × Rule Engine 邏輯判定協作**：目前 Rule Engine 使用 Regex，無法處理非標準中文表達。Phase 2 計畫引入 LLM 先將自然語言條款正規化為結構化數值，再由 Rule Engine 進行邏輯比對，保留可驗證性的同時提升語意彈性。
2. **異質模型 MAS**：引入 Gemini + Claude 雙模型，從根本解決 Echo Chamber 問題。
3. **Human Evaluation**：量化 Pending 機制對使用者決策品質的實際影響。
