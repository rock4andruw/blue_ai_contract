## 二、核心貢獻（說服口試委員的三個重點）

**C1 — 防禦性三層設計**
針對已知風險類別（15 類），Rule Engine 以純程式規則達到該範圍內 100% 召回率，不依賴 LLM，結果可重現可驗證。對規則庫未涵蓋的長尾風險（非標準寫法、新型條款），由 Verification Agent（LLM 語意補漏）負責偵測。兩層互補，形成「已知風險不漏判、未知風險有補網」的防禦設計。

> **重要範圍說明**：100% 召回率的主張成立於預定義的 15 類風險類別，並非對所有可能的合約風險。論文中需明確說明此範圍，避免過度宣稱。

**C2 — 盲評 MAS 防止 Sycophancy**
基於 *When Truth Is Overridden (2025)*，Agent 不知 Rule Engine 答案、不知對方答案，獨立判斷。在繁體中文合約場景首次實作驗證。

**C3 — Pending 機制揭露 AI 不確定性**
模糊條款出現時主動標記「待確認」，讓人工判斷，而非讓 AI 猜。比強制輸出確定答案更適合法律場景。

## 三、研究問題

**RQ1**：混合架構（Rule Engine + LLM）相較於純 LLM，在繁體中文合約風險偵測中是否達到更高的高風險召回率？

**RQ2**：盲評設計是否有效降低雙代理人系統中的 Sycophancy，提升與人工標注的一致性？

**RQ3**（選做）：AI 主動揭露不確定性（Pending 機制）是否改善使用者決策品質？

## 四、系統架構（已完成，畢業論文第三章主體）

```
原始合約 + 修訂合約
        │
        ▼
  Contract Parser（MD / PDF / DOCX 條款切分）
        │
        ▼
  Clause Alignment（LCS + Needleman-Wunsch DP，相似度 ≥ 75% 後處理）
        │
        ▼
  Diff Engine（新增 / 修改 / 刪除，DiffItem 標準化輸出）
        │
        ├──────────────────────────┐
        ▼                          ▼
  [Layer 1]                  [Layer 2]
  Risk Rule Engine            Verification Agent
  14 條純 Python 規則          LLM 語意補漏掃描
  預定義類別內 100% 召回        捕獲 Regex 未覆蓋的非標準寫法
        │                          │
        └────────┬─────────────────┘
                 ▼
        交叉核對（A. 雙軌確認 / B. 規則觸發 / C. 補漏警示）
                 │
                 ▼
        MAS 盲評雙重驗證
        Agent A（嚴格：最壞情況視角）
        Agent B（平衡：台灣業界慣例視角）
        → 互不知對方答案，不知 Rule Engine 結果
                 │
                 ▼
        Judge 矩陣
        gap = 0/1 → confirmed（嚴格優先）
        gap = 2   → pending（需人工判斷）
        失敗       → single_agent（靜默退級）
                 │
                 ▼
        Report Generator（Markdown 報告 + MAS 雙重驗證標籤）
```

**設計原則**：Rule Engine 判斷已知風險（保 Recall）→ Verification Agent 補漏未知風險（保覆蓋率）→ LLM 解釋（保可讀性）→ MAS 驗證（保可信度）

> **LLM 與程式碼的角色分工**：Rule Engine 與 LLM 在偵測階段是**串聯**而非協作——Rule Engine 先獨立偵測，LLM 在後段負責白話解釋與協商對策生成，不參與風險等級判定。此設計確保偵測結果不受 LLM 幻覺影響。未來研究（Phase 2）計畫引入「LLM 語意解析 → Rule Engine 邏輯判定」的協作模式，以解決非標準中文寫法的偵測問題。

## 五、實驗設計（畢業論文最小可行版）

### Experiment 1：召回率比較（RQ1）—— 必做，約 1 週

**對照組：**

| 系統 | 描述 |
| --- | --- |
| B1 — LLM Zero-shot | Diff 直接送 LLM，zero-shot 判斷風險 |
| B2 — Rule Engine Only | 只跑 14 條規則，關掉 LLM |
| B3 — 本系統（無 MAS） | Rule Engine + LLM，無雙重驗證 |
| **本系統（完整）** | Rule Engine + LLM + MAS 盲評 |

**評估指標**：High-risk Recall（主）、Precision、F1

---

### Experiment 2：盲評 vs. 非盲評（RQ2）—— 必做，約 3 天

```text
同一批合約，分兩條路跑 MAS：

路徑 A（盲評，本系統）：Agent B 不知 Agent A 答案 → 獨立判斷
路徑 B（非盲評，對照）：Agent B 先看 Agent A 答案 → 再回答

量化 Sycophancy 率：Agent B 改變立場次數 / 總判斷次數
比較兩條路與 gold set 的一致性
```

這個實驗是論文最有學術價值的部分，改幾行程式碼就能跑。
